**游戏里目前的怪物**：史莱姆、黏液怪和钻头怪。钻头怪巢穴加入正常发现，最多一座；钻头怪只在冒头时可吸取，地下不随机叫。

## 已接入主游戏的声音

### 近景 / 全景的声音规则

切到**星球全景（总览）**时，近景玩法的声音全部静音；切回近景时恢复。

| 全景下静音 | 全景下照常播放 |
|---|---|
| 怪物（巢穴出现、出洞、随机叫声）、吸尘器、黏液进出、吸走 Pop、糖果声、捕网（`Net_Cast` / `Net_Capture`） | 背景音乐、按钮 / UI 声、星球转动 `AnimationSystem/Earth_Rotate` |

- 声音只是"听不到"，游戏逻辑照常在后台运行：怪物照样出洞、叫声的计时和出洞声限流都继续计算，切回近景时不会突然补播一堆。
- 音量跟着镜头的缩放过渡一起变化，不是一下子切断。
- 在全景下直接返回主菜单，下次进游戏近景声音会正常恢复。
- 哪些事件算"近景声音"在 `scripts/fmod_audio.gd` 开头的 `NEAR_VIEW_PREFIXES` 里定义，新增近景事件时按命名前缀加一行即可。

### 静音和音量（2026-10-14）

- 游戏右上角的声音按钮同时开关背景音乐、FMOD 音效和 Godot 原生音效；再次开启恢复原有音乐／音效音量。设置页在静音时两项都显示“已关闭”，滑块保留原值。调高任一音量会开启游戏声音。
- 游戏暂停（暂停按钮、设置页或科技页）时，FMOD 音乐与音效一同暂停，原生音效输出也静音；恢复后从原位置继续，保留玩家音量与编辑器静音状态。音乐淡入淡出及转场计时也随游戏暂停。
- Godot 运行窗口工具栏的静音按钮也同步控制 FMOD 总线；运行前静音、运行中切换以及重新运行均生效。编辑器静音不写入玩家偏好，与游戏静音分别生效，必须两者都开启声音才有输出。
- 编辑器同步插件为 `addons/planet_audio_mute/`，已在项目配置中启用。已打开的编辑器需要重开项目以加载插件，旧的游戏进程也需要重新运行。插件依赖 Godot 4.7 的 Game view 按钮结构，升级引擎时用编辑器专项检查确认。
- Godot 4.7.2 的菜单声音检查、原有 FMOD 集成检查与实际编辑器按钮通信检查通过。编辑器专项以 `--headless --editor --script tests/editor_audio_mute_check.gd` 运行，覆盖运行中开关、两种静音状态互不覆盖及重启继承；菜单入口仍为 `tests/game_menu_check.tscn`。

本次 1280×800／1920×1080 的静音按钮和设置页新截图位于 `artifacts/audio_mute_visual_20261014/`，已查看两项“已关闭”与静音图标。该次截图运行另有游玩预览的 `emergence_progressed` 信号缺失报错，相关巢穴演出代码未在音频修改中调整；不据此声称完整游玩预览启动无错误。

- **启动音量**：**每次打开游戏**，音乐和音效推子都重置为 **90%**，声音处于开启状态，不沿用上次调整的音量或静音。游戏过程中调整的音量只在本次运行内有效。点"恢复默认"、或两个推子都为 0 时重新打开声音，也回到 90%。全屏设置仍会保留。

- **暂停时的声音**：打开**设置**、**科技树**或手动暂停时，音乐和按钮／升级等 UI 声音照常播放，玩法音效（吸尘器、怪物、糖果、捕网等）原地冻结，关闭后从停住处继续。
- **菜单低通（Music_Menu）**：上述暂停期间，游戏把全局参数 `Music_Menu`（0–1）在 0.3 秒内推到 1，关闭时 0.3 秒回到 0（`scripts/fmod_audio.gd` 的 `music_menu_fade_seconds`）。**需要在 FMOD 里搭**：新建全局连续参数 `Music_Menu`，在 `Mx/Mx_GamePlay`（以及希望受影响的其他音乐）的 Master 上加 Multiband EQ 低通，截止频率 0 → 22 kHz，1 → 800 Hz。FMOD 里没有这个参数时游戏不传，也不报错。

### 背景音乐

| 音乐 | FMOD 事件 | 什么时候播放 |
|---|---|---|
| 开头动画音效 | `Mx/OpeningAnimation` | 游戏启动、开头动画开始时同步播放（一次性，约 14.6 秒） |
| 主菜单音乐 | `Mx/Mx_MainMenu` | 进入主菜单时开始，循环播放 |
| 游戏音乐 | `Mx/Mx_GamePlay` | 从主菜单点"开始"（或从预览列表进入近景 / 全景游玩）后开始，循环播放。随游戏进度分三个阶段交叉切换（见"音乐阶段划分"） |

- **开头动画音效**：动画约 10.8 秒，音效约 14.6 秒。
  - 同步：动画先停在第一帧，等音效真正开始出声（FMOD 约 0.2 秒启动延迟）再一起走；之后动画以音效的时间为准，加载卡顿后会自动追上（实测卡顿 0.6 秒后两帧内重新对齐，平时误差约 ±20 毫秒）。
  - 尾巴不切：动画结束进入主菜单后，音效继续播放到结束（多出的约 3.8 秒尾巴会和主菜单音乐的开头重叠）。
- 循环在 FMOD 里做好（循环区域），游戏只负责开始和停止。
- **近景 / 远景换 stem**：游戏音乐由多个同步 stem 组成。近景播 stem A + B，切到远景（星球全景）变成 stem A + C。由参数 `IsDistantView` 控制（0 = 近景，1 = 远景；目前在 FMOD 里是全局参数，改成事件内参数游戏也会自动适应），游戏每帧按镜头缩放进度连续设置，所以 B / C 的交叉和画面拉远拉近同步进行。
- **从主菜单点"开始"**：主菜单音乐立刻停止，同时播放过渡音效 `AnimationSystem/GameStart_Transition`；**游戏音乐紧接在过渡音效之后开始**，中间没有空隙，也不重叠。场景加载期间过渡音效照常播放，加载时间长短不影响它。
  - 衔接方式：点"开始"的瞬间，游戏音乐就以暂停状态预先准备好；游戏场景改为**后台加载**，加载期间画面停在主菜单（按钮暂时不可点），游戏这边不卡顿，音乐可以准时开始。
  - 进入时机：过渡音效全长 3.43 秒，但约 2.4 秒后已降到 −40 dB 以下（比游戏音乐轻 20 dB 以上，基本听不到）。游戏音乐在约 2.45 秒进来，只和这段几乎无声的尾巴重叠，听感上是无缝衔接。实测冷启动、热启动都在点击后约 2.5 秒出声。
  - 第一次进游戏时场景加载可能比过渡音效还长（实测冷启动约 4.2 秒），这时游戏音乐会在主菜单画面上先响起，场景加载完再切到游戏画面。
  - 衔接后游戏音乐直接以正常音量开始，不再从无声淡入。
  - 换了过渡音效素材后，可在 `scripts/fmod_audio.gd` 的 `transition_music_lead_seconds`（当前 1.2 秒）微调：听到空隙就调大，听到重叠就调小。
  - 主菜单音乐是"立刻停"还是"淡出后停"，由 FMOD 里 `Mx_MainMenu` 自身的设置决定（比如 Master 上加 AHDSR 的 Release）；目前没有设置，是直接停止。
  - 保险：如果过渡音效 15 秒后仍未结束，游戏音乐也会开始。
  - 只有主菜单的"开始"按钮走这个过渡；从预览列表直接进入近景 / 全景游玩时，仍是普通的交叉淡入淡出。
- **其他切换时交叉淡入淡出**：新音乐用 0.3 秒从无声淡入，旧音乐同时用 0.3 秒淡出后停止。主菜单 → 游戏 → 返回主菜单都是这样。
- 进游戏要加载场景，加载期间主菜单音乐会继续播放，加载完才开始交叉淡变，不会出现中途卡住或突然变静音。
- 第一次进入主菜单时，主菜单音乐也会淡入。
- 两个时长可以在 `scripts/fmod_audio.gd` 开头的 `music_fade_in_seconds` / `music_fade_out_seconds` 调整。

### 怪物

| 声音 | 史莱姆怪 | 黏液怪 | 玩家什么时候会听到 |
|---|---|---|---|
| 巢穴出现 | `Monsters/Slime_NestAppear` | `Monsters/Mucus_NestAppear` | 游戏中途星球上长出一座新巢穴时。开局就在的两座史莱姆巢穴不播 |

| 随机叫声 | `Monsters/SlimeMon_Rand` | `Monsters/MucusMon_Rand` | 星球上有这种怪物时随机发出。数量越多叫得越频繁（见下方说明） |

**出洞声的防爆音规则**

巢穴会一次吐出一波怪物（满级巢穴一波最多约 18 只），如果每只都播一次出洞声会叠成爆音。现在的规则：

- **一波只播几声**：同一帧刷出的同种怪物，最多播 3 声，依次间隔约 0.08 秒（带一点随机），听起来像"噗噗噗"连着出洞，而不是一声巨响。
- **全局上限**：所有巢穴、所有怪物加起来，任意 0.5 秒内最多 4 声出洞声；超出的直接不播（不会攒到后面补播）。
- **最小间隔**：任意两声出洞声至少相隔 0.05 秒，几座巢穴同时刷怪也不会在同一瞬间叠加。
- 实测：同一帧刷出 18 只史莱姆 + 10 只黏液怪，只播 4 声，分布在约 0.16 秒内；紧接着 0.25 秒后的第二波 12 只全部静音；0.5 秒后恢复正常。
- 数值都在 `scripts/monster_audio.gd` 开头（`burst_max_voices`、`burst_stagger_seconds`、`trigger_max_per_window`、`trigger_window_seconds`、`trigger_min_gap_seconds`）。
- 建议在 FMOD 里也给三个 `XMon_Trigger` 事件设置 Max Instances（比如 4）作为第二道保险。

**随机叫声的频率规则**（两种怪物各自独立计算）：

- 每只在星球上的怪物，平均每秒贡献 0.06 次叫声，大约每只 17 秒叫一次。
- 同一种怪物加起来最多每秒 1.2 次，怪物再多也不会更吵。
- 同一种怪物两次叫声之间至少间隔 0.25 秒，避免叠在一起。
- 例子：5 只史莱姆，大约每 3 秒叫一声；20 只及以上，达到上限，大约每秒 1 声多。
- 这三个数值都可以在 `scripts/monster_audio.gd` 里调整。

### 吸走与糖果

| 声音 | FMOD 事件 | 玩家什么时候会听到 |
|---|---|---|
| 吸走怪物 | `Vacuum/SuckUp_Pop` | 每只怪物被吸管吸走的那一刻（捕网抓到的不播） |
| 吸走钻头怪 | `Vacuum/DrillMon_SuckUp` | 钻头怪被吸管吸走的那一刻，**代替** `SuckUp_Pop`（钻头怪不再播 Pop）。bank 里没有这个事件时退回 `SuckUp_Pop` |
| 抓到金色怪物 | `Golden_Mon` | 金色（高价值）怪物被吸管吸走的那一刻，或捕网网到金色怪物时（一网只响一次，不论网到几只金色）。和普通的吸走 / 糖果声同时触发 |
| 吸管拿到糖果 | `Candy_Acquire` | `SuckUp_Pop` 响后 **0.15 秒**响第一声，不和 Pop 同时触发；之后按抓到的怪物数量连响（见下方"糖果连响"） |
| 捕网拿到糖果 | `Candy_Acquire` | `Net_Capture` 响后 **0.2 秒**响第一声（等它的主体打完，避免被盖住），按这一网抓到的只数连响。没网到怪物不响。原来的 `Candy_Nest` 已不再使用 |

**糖果连响（按抓到的怪物数量）**

- 抓到几只怪物就响几声 `Candy_Acquire`，和糖果数量无关。吸管吸一只普通怪物只响一声；巨型史莱姆按它相当于几只小怪来算，捕网按这一网抓到的只数来算，**一次最多 12 声**。
- 声音不会叠在一起：第一声立刻响，第二声隔 0.15 秒，之后每次间隔缩短为上一次的 85%，最短 0.05 秒。
- 每多响一声，音量比上一声低 6%（第二声 94%，第三声约 88%，依此类推）。2026-10-16 之前这个递减会在 0.1 秒内被游戏的音量刷新覆盖回 100%，连响实际都是满音量；现已修复。
- 几次收获的连响可以同时在排队，排队总数不超过 12 声。
- **糖果数值参数 `Candy_Value`（需要在 FMOD 里给 `Candy_Acquire` 加上）**：游戏会传入"平均每只怪物值多少糖果"，按对数换算到参数范围内：1 颗 → 参数最小值，250 颗及以上 → 参数最大值（约 16 颗在中间）。参数范围在 FMOD 里随意设，游戏会读取实际的最小值和最大值。FMOD 里还没有这个参数时游戏不会传，也不会报错。
- 数值都在 `scripts/monster_audio.gd` 开头：`candy_after_pop_seconds`（吸管 Pop 后的延迟，0.15）、`candy_after_net_seconds`（`Net_Capture` 后的延迟，0.2）、`candy_max_voices`（12）、`candy_first_gap_seconds`（0.15）、`candy_gap_decay`（0.85）、`candy_min_gap_seconds`（0.05）、`candy_volume_decay`（0.94）、`candy_value_full`（250）。

**糖果连击音调（参数 `Candy_Combo`，0–1）**

- 跟随新的**连击爬梯**：4 段（目标 3／5／7／10 只，每段 5 秒）平分 0–1。第 1 段在 0–0.25 之间爬，第 2 段 0.25–0.5，第 3 段 0.5–0.75，第 4 段 0.75–1。完成一段的那一声在这一段的顶点。中断或完成已开放的最高段后回到起点。只解锁前几段时，最高只到对应位置（如只解锁 2 段最高 0.5）。
- 没研究"连击爬梯"时为 0。只有吸管吸取算连击；捕网拿到的糖果固定为 0。
- 数值在结算之前读取，避免"完成一段那一下连击已归零、音调掉到最低"。

### 星球颜色恢复（2026-10-14）

| 声音 | FMOD 事件 | 玩家什么时候会听到 |
|---|---|---|
| 第一次上色 | `AnimationSystem/ColorRecover_Stage1` | 本局**第一次**物种颜色恢复：镜头拉到全景后，星球开始被这种颜色填满的那一刻 |
| 第二、三次上色 | `AnimationSystem/ColorRecover_Stage2` | 本局第二次、第三次物种颜色恢复，同上（两次用同一个事件） |
| 最终变白 | `AnimationSystem/ColorRecover_Stage3` | 所有巢穴都自动化后，整个画面背景变白的那一刻 |

- **上色的触发条件**：某一种怪物（史莱姆、黏液怪、钻头怪）的巢穴**第一次**被驯服变成花时，恢复这种怪物对应的颜色。同一种怪物的第二朵花不会再触发。顺序由玩家先驯服哪种决定，事件按发生顺序选，不对应固定物种。第一次可能在游戏中期就发生；整局没出现过某种巢穴的话就少一次。
- **上色的画面顺序**：变花后停 0.8 秒确认 →（在近景时）地平线地形先上色 0.9 秒 → 镜头拉到全景 → **星球颜色填充 2.4 秒（此刻触发音效）**。第三次填充结束后紧接着"星核淡出、换成恢复后的动态星球"约 1 秒，这一段没有单独音效。
- **变白的触发条件**：当前所有巢穴都已自动化，背景约 1 秒变白。不要求三种颜色都恢复过；如果最后一次驯服同时带来新颜色，会先上色、再变白。
- 颜色恢复发生在全景下，所以不受"全景静音"影响。演出中镜头拉到全景**不再播 `UI/ZoomOut`**。
- 代码：`scripts/planet_restoration.gd` 发出 `color_fill_started(stage)` 和 `background_restore_started`，`scripts/planet_audio.gd` 选择并播放事件。

### 演出期间的音乐闪避（Music_Duck）

- **新巢穴出现演出**和**星球颜色恢复演出**的整个过程中，游戏把全局参数 `Music_Duck` 在 0.4 秒内推到 1，演出结束后 0.4 秒内回到 0。两种演出接连发生时保持闪避不反弹。重开游戏或离开游戏场景时立刻释放。
- **需要在 FMOD 里搭**（游戏使用的 FMOD 插件不能在运行时直接挂滤波器）：新建全局连续参数 `Music_Duck`（0–1），在 `Mx/Mx_GamePlay` 的 Master 上用它自动化：音量 0 → −6 dB；加一个低通（或 Multiband EQ 的低通段），截止频率 0 → 关闭／22 kHz，1 → 1000 Hz。FMOD 里没有这个参数时游戏不会传，也不会报错。
- 淡入淡出时长在 `scripts/fmod_audio.gd` 的 `music_duck_fade_seconds`（0.4 秒）。

### 听感上的设计意图（吸尘器）

- 吸管口在黏液里时，吸尘器的运转声会变闷（低通），离开时"啵"一声恢复清晰。
- 连续吸怪时，吸完一只后很快锁定下一只，吸尘器会一直开着，不会每只都关一次再开一次。
- 吸尘器关机时如果吸管口还在黏液里，会直接恢复清晰，不播"啵"声，避免关机时出现奇怪的 Pop。
- 只有吸尘器开着时，黏液声才会触发；吸管空着划过黏液不会出声。

钻头怪三个事件 `Drill_NestAppear`、`DrillMon_Trigger`、`DrillMon_Rand` 已接入巢穴发现、单只出洞与冒头随机叫声。

## 音乐阶段划分（已按推荐方案接入）

> 状态：2026-10-12 已接入，采用下方"推荐方案"（中期 = 第三次基础价值突破，后期 = 研究完全自动化）。阶段条件仍可在试玩后调整。三个阶段的背景音乐不同，由 FMOD 的交互音乐系统切换。

**当前实现**

- FMOD：`Mx_GamePlay` 里三层音乐时间线同步，全局连续参数 `GameStage`（0–2）控制各层音量，参数上的 Seek 调制器把每次切换变成交叉淡变。0 = Stage 1，1 = Stage 2，2 = Stage 3。
- 游戏：每次购买或经济变化后检查进度，跨过里程碑时把 `GameStage` 设为 1 或 2；**只进不退**；重开游戏回到 0。
- 如果玩家先研究了完全自动化、还没做第三次价值突破，会直接从 0 进到 2（FMOD 的 Seek 会依次滑过 Stage 2）。
- 触发条件在 `scripts/disk_demo.gd` 开头的 `MUSIC_MID_BASE_VALUE_LEVEL`（3）和 `MUSIC_LATE_GOVERNANCE_LEVEL`（3）。

### 一局游戏怎么推进

1. 开局两座史莱姆巢穴，只有吸管。新巢穴不会出现（开局保护 60 秒，并且要先解锁捕网）。
2. 解锁捕网后，星球开始随机长出新巢穴，黏液怪、钻头怪陆续登场。
3. 研究"巢穴培育"后可以升级巢穴；研究"完全自动化"后，巢穴升到顶级会被驯服（变成花、自动产糖）。
4. 所有巢穴都自动化即通关。

### 推荐方案

| 阶段 | 开始条件 | 理由 |
|---|---|---|
| **早期** | 开局 | 熟悉吸管，经济起步 |
| **中期** | **第三次基础价值突破**（900 糖果，史莱姆 5→10 糖果） | 超过 400 糖果；是科技树中央的核心经济节点，几乎每个玩家都会买；买完后收入翻倍，玩法节奏明显加快。此时通常已解锁捕网、出现新物种 |
| **后期** | **研究完全自动化**（7500 糖果） | 整局最贵的一笔投入；买完后进入"逐个驯服巢穴、星球开花"的收尾阶段 |
| （结尾） | 通关（全部巢穴自动化） | 可另做一段结尾音乐或 stinger，不占用三个阶段 |

**参考时间线**：README 里的脚本自动试玩（调价前）记录，四次基础价值突破在 41／115／167／255 秒，第一座巢穴自动化 273 秒，全部完成 306 秒。按推荐方案，脚本里大约是：早期 0–167 秒、中期 167–约 265 秒、后期约 265–306 秒。脚本玩得比真人快很多，**真人时长需要试玩实测**；但可以看出后期相对较短，因为后期收入增长很快。后期音乐建议按"高潮、可以较短"来设计，或者把后期起点提前（见下面的备选）。

## 需要制作人留意的点

- **"新巢穴出现后有两个 BGM"（2026-10-16 排查）**：实测从主菜单进游戏并触发第一次新巢穴演出，全程只有一个 `Mx_GamePlay` 实例，没有第二条音乐。叠在 BGM 上的是 `New_Nest`（8.7 秒，含带延迟的颤音琴和弦）和背景变色的 `ColorChange_*`，变色约 10 秒后切回优势物种时还会再响一次。游戏会推 `Music_Duck` 压低音乐，但当前 FMOD 工程里还**没有** `Music_Duck` 和 `Music_Menu` 这两个参数，所以演出期间音乐没有被压低。目前只有 Animation 总线对 Mx 的侧链压缩（阈值 −24 dB），`New_Nest` 较轻的段落压不下去。建议在 FMOD 里按下方"演出期间的音乐闪避"搭好 `Music_Duck`，或者把 `New_Nest` 里的音乐性元素与 BGM 的调对齐。
- **噪音／杂音（排查中，尚未定位到唯一原因）**：Master 总线上没有限幅器，音乐、连响糖果和演出音效叠加时可能削波；Mx 总线挂了三个压缩器，分别被 SFX、Animation、Combo 侧链触发，玩法音效一密集，音乐就会被反复压下、放开（抽吸感）。游戏这边修了糖果连响音量递减失效（见"糖果连响"）。建议在 FMOD 的 Master 上加一个 Limiter，并在 Profiler 里看 Master 的电平是否到 0 dBFS。

- **试听方式**：打开项目按 F5 运行主游戏即可。鼠标悬停怪物开始吸；黏液怪巢穴解锁后，去有黏液的地面上吸怪，可以听到黏液效果。
- **开机时机是"锁定怪物"而不是"鼠标在星球上"**：只有真正在吸东西时吸尘器才响，空闲时安静。如果试玩觉得开关太频繁，可以改成"吸管在星球表面就开机"，或者调长 0.2 秒的关机缓冲。
- **原来的收集音效（WAV）已被替换**：吸走怪物改为 `SuckUp_Pop` + `Candy_Acquire`，捕网收获也用 `Candy_Acquire` 连响。如果 bank 缺失或加载失败，会自动退回原来的 WAV，游戏不会没声音。
- 怪物声音是全局的（2D），不分左右、不随距离变小；在星球全景里静音（见上方"近景 / 全景的声音规则"）。
- 切到星球总览、移到 UI 上时，吸管口会被视为离开黏液，可能先听到一声 Pop 再关机。试玩时如果觉得别扭，请反馈。

## 更新声音的流程

音频同事在 FMOD Studio 里改完声音后，Build 出三个文件（`Master.bank`、`Master.strings.bank`、`ProjectVacuum.bank`），覆盖到项目的 `bank/Desktop/` 文件夹即可。只要事件名不变，游戏不需要改代码。

**在 FMOD 里移动 event 到别的文件夹（2026-10-15 起）**：游戏会按 event **名字**自动找到它，不需要改代码。找到时会在 Godot 输出里提示一行 `FMOD event ... moved; using ...`。注意：

- **改名**仍然要告诉我，游戏是按名字找的。
- 不要让两个文件夹里出现**同名** event，否则游戏不知道用哪个，会提示 `ambiguous` 并当作找不到。
- 全景静音按文件夹判断（`Monsters/`、`Vacuum/`、`Candy/`、`Net/`，以及三个 `*_NestAppear`）。把近景玩法的 event 移出这些文件夹，它在全景下就不再静音；把别的 event 移进来，它在全景下会被静音。音乐按名字 `Mx_` 开头识别，不受文件夹影响。
