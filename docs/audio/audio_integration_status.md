# 音频接入进度（给制作人）

音频更新：2026-10-11 · Fred 的 `OCT11-AudioUpdate` 已与最新玩法合并到 `main` · 负责人：Fred（音频）

这份文档记录主游戏里**哪些声音已经接入、什么时候会响、还差什么**。技术细节见同目录下的其他手册；这里只写玩法层面需要知道的内容。每次音频接入有进展都会更新这里。

## 一句话现状

吸尘器（开关机、黏液）、怪物（巢穴出现、出洞、随机叫声）、吸走怪物、拿到糖果、按钮和科技升级，以及主菜单和游戏中的背景音乐，已经通过 FMOD 接入。巢穴培育升级、驯服、通关音效暂时还是原来的 Godot 音效。钻头怪现已接入巢穴出现、出洞和冒头时的随机叫声；吸走和糖果回袋复用现有反馈。

**游戏里目前的怪物**：史莱姆、黏液怪和钻头怪。钻头怪巢穴加入正常发现，最多一座；钻头怪只在冒头时可吸取，地下不随机叫。

## 已接入主游戏的声音

### 近景 / 全景的声音规则

切到**星球全景（总览）**时，近景玩法的声音全部静音；切回近景时恢复。

| 全景下静音 | 全景下照常播放 |
|---|---|
| 怪物（巢穴出现、出洞、随机叫声）、吸尘器、黏液进出、吸走 Pop、糖果声 | 背景音乐、按钮 / UI 声、星球转动 `Earth_Rotate` |

- 声音只是"听不到"，游戏逻辑照常在后台运行：怪物照样出洞、叫声的计时和出洞声限流都继续计算，切回近景时不会突然补播一堆。
- 音量跟着镜头的缩放过渡一起变化，不是一下子切断。
- 在全景下直接返回主菜单，下次进游戏近景声音会正常恢复。
- 哪些事件算"近景声音"在 `scripts/fmod_audio.gd` 开头的 `NEAR_VIEW_PREFIXES` 里定义，新增近景事件时按命名前缀加一行即可。

### 背景音乐

| 音乐 | FMOD 事件 | 什么时候播放 |
|---|---|---|
| 主菜单音乐 | `Mx_MainMenu` | 进入主菜单时开始，循环播放 |
| 游戏音乐 | `Mx_GamePlay` | 从主菜单点"开始"（或从预览列表进入近景 / 全景游玩）后开始，循环播放。随游戏进度分三个阶段交叉切换（见"音乐阶段划分"） |

- 循环在 FMOD 里做好（循环区域），游戏只负责开始和停止。
- **近景 / 远景换 stem**：游戏音乐由多个同步 stem 组成。近景播 stem A + B，切到远景（星球全景）变成 stem A + C。由参数 `IsDistantView` 控制（0 = 近景，1 = 远景；目前在 FMOD 里是全局参数，改成事件内参数游戏也会自动适应），游戏每帧按镜头缩放进度连续设置，所以 B / C 的交叉和画面拉远拉近同步进行。
- **从主菜单点"开始"**：主菜单音乐立刻停止，同时播放过渡音效 `GameStart_Transition`；**游戏音乐紧接在过渡音效之后开始**，中间没有空隙，也不重叠。场景加载期间过渡音效照常播放，加载时间长短不影响它。
  - 衔接方式：点"开始"的瞬间，游戏音乐就以暂停状态预先准备好；游戏场景改为**后台加载**，加载期间画面停在主菜单（按钮暂时不可点），游戏这边不卡顿，音乐可以准时开始。
  - 进入时机：过渡音效全长 3.43 秒，但约 2.4 秒后已降到 −40 dB 以下（比游戏音乐轻 20 dB 以上，基本听不到）。游戏音乐在约 2.45 秒进来，只和这段几乎无声的尾巴重叠，听感上是无缝衔接。实测冷启动、热启动都在点击后约 2.5 秒出声。
  - 第一次进游戏时场景加载可能比过渡音效还长（实测冷启动约 4.2 秒），这时游戏音乐会在主菜单画面上先响起，场景加载完再切到游戏画面。
  - 衔接后游戏音乐直接以正常音量开始，不再从无声淡入。
  - 换了过渡音效素材后，可在 `scripts/fmod_audio.gd` 的 `transition_music_lead_seconds`（当前 1.2 秒）微调：听到空隙就调大，听到重叠就调小。
  - 主菜单音乐是"立刻停"还是"淡出后停"，由 FMOD 里 `Mx_MainMenu` 自身的设置决定（比如 Master 上加 AHDSR 的 Release）；目前没有设置，是直接停止。
  - 保险：如果过渡音效 15 秒后仍未结束，游戏音乐也会开始。
  - 只有主菜单的"开始"按钮走这个过渡；从预览列表直接进入近景 / 全景游玩时，仍是普通的交叉淡入淡出。
- **其他切换时交叉淡入淡出**：新音乐用 0.3 秒从无声淡入，旧音乐同时用 0.3 秒淡出后停止。主菜单 → 游戏 → 返回主菜单都是这样。
- 进游戏要加载场景，加载期间主菜单音乐会继续播放，加载完才开始交叉淡变，不会出现中途卡住或突然变静音。
- 第一次进入主菜单时，主菜单音乐也会淡入。
- 两个时长可以在 `scripts/fmod_audio.gd` 开头的 `music_fade_in_seconds` / `music_fade_out_seconds` 调整。

|---|---|---|---|
| 巢穴出现 | `Monsters/Slime_NestAppear` | `Monsters/Mucus_NestAppear` | 游戏中途星球上长出一座新巢穴时。开局就在的两座史莱姆巢穴不播 |

| 随机叫声 | `Monsters/SlimeMon_Rand` | `Monsters/MucusMon_Rand` | 星球上有这种怪物时随机发出。数量越多叫得越频繁（见下方说明） |

**出洞声的防爆音规则**

巢穴会一次吐出一波怪物（满级巢穴一波最多约 18 只），如果每只都播一次出洞声会叠成爆音。现在的规则：

- **一波只播几声**：同一帧刷出的同种怪物，最多播 3 声，依次间隔约 0.08 秒（带一点随机），听起来像"噗噗噗"连着出洞，而不是一声巨响。
- **全局上限**：所有巢穴、所有怪物加起来，任意 0.5 秒内最多 4 声出洞声；超出的直接不播（不会攒到后面补播）。
- **最小间隔**：任意两声出洞声至少相隔 0.05 秒，几座巢穴同时刷怪也不会在同一瞬间叠加。
- 实测：同一帧刷出 18 只史莱姆 + 10 只黏液怪，只播 4 声，分布在约 0.16 秒内；紧接着 0.25 秒后的第二波 12 只全部静音；0.5 秒后恢复正常。
- 数值都在 `scripts/monster_audio.gd` 开头（`burst_max_voices`、`burst_stagger_seconds`、`trigger_max_per_window`、`trigger_window_seconds`、`trigger_min_gap_seconds`）。
- 建议在 FMOD 里也给三个 `XMon_Trigger` 事件设置 Max Instances（比如 4）作为第二道保险。

**随机叫声的频率规则**（两种怪物各自独立计算）：

- 每只在星球上的怪物，平均每秒贡献 0.06 次叫声，大约每只 17 秒叫一次。
- 同一种怪物加起来最多每秒 1.2 次，怪物再多也不会更吵。
- 同一种怪物两次叫声之间至少间隔 0.25 秒，避免叠在一起。
- 例子：5 只史莱姆，大约每 3 秒叫一声；20 只及以上，达到上限，大约每秒 1 声多。
- 这三个数值都可以在 `scripts/monster_audio.gd` 里调整。

### 吸走与糖果

| 声音 | FMOD 事件 | 玩家什么时候会听到 |
|---|---|---|
| 吸走怪物 | `SuckUp_Pop` | 每只怪物被吸管吸走的那一刻（捕网抓到的不播） |
| 吸管拿到糖果 | `Candy_Acquire` | 和 `SuckUp_Pop` **同时**触发，也就是怪物被吸走的那一刻，不等糖果飞到计数器 |
| 捕网拿到糖果 | `Candy_Nest` | 捕网收网、网到怪物并得到糖果的那一刻（一网一次，网到几只都只响一次）。没网到怪物不响 |

**糖果连击音调（参数 `Candy_Combo`，0–1）**

- 跟随游戏里的连击数：连击 0 时为 0，每多一连击加 0.1，**第 10 连击及以后达到最高值 1**。
- 游戏的连击需要先在科技树里解锁"连击吸取"，并且只有吸管连续吸怪才算连击（两次之间不超过连击时限）。没解锁之前音调不会上升。
- 连击音调只用于吸管的 `Candy_Acquire`；捕网用的是单独的 `Candy_Nest`，不受连击影响。

### 星球

| 声音 | FMOD 事件 | 玩家什么时候会听到 |
|---|---|---|
| 星球转动 | `Earth_Rotate` | 右键拖动、**星球真的在转**时循环播放；停止转动或松开后，按 FMOD 里设置的淡出停止。近景和星球总览里的拖动都算 |

- **按住右键但星球没转，不算拖动**：鼠标停住约 0.12 秒后声音淡出；继续拖动时重新从头播放。
- **拖动中换方向，事件从头重新触发**：旧的声音按 FMOD 淡出，新的从头开始。为了不被手抖误触发，要往反方向拖约 7 像素（近景下）才算换方向。
- 总览视图里星球自己缓慢自转时不播，只有玩家拖动才播。
- 0.12 秒和"换方向阈值"两个数值可以在 `scripts/planet_audio.gd` 开头调整。

| 声音 | FMOD 事件 | 玩家什么时候会听到 |
|---|---|---|
| 镜头拉近 | `ZoomIn` | 从全景切换到近景的动画开始时（滚轮、按钮、点击全景气泡都算） |
| 镜头拉远 | `ZoomOut` | 从近景切换到全景的动画开始时 |

- 只有带动画的镜头切换才播。重开游戏时视角直接复位、从预览列表直接进入全景游玩，都不播。
- 缩放音效不受"全景静音"影响，两种视角下都能听到。

### 听感上的设计意图（吸尘器）

- 吸管口在黏液里时，吸尘器的运转声会变闷（低通），离开时"啵"一声恢复清晰。
- 连续吸怪时，吸完一只后很快锁定下一只，吸尘器会一直开着，不会每只都关一次再开一次。
- 吸尘器关机时如果吸管口还在黏液里，会直接恢复清晰，不播"啵"声，避免关机时出现奇怪的 Pop。
- 只有吸尘器开着时，黏液声才会触发；吸管空着划过黏液不会出声。

钻头怪三个事件 `Drill_NestAppear`、`DrillMon_Trigger`、`DrillMon_Rand` 已接入巢穴发现、单只出洞与冒头随机叫声。

## 音乐阶段划分（已按推荐方案接入）

> 状态：2026-10-12 已接入，采用下方"推荐方案"（中期 = 第三次基础价值突破，后期 = 研究完全自动化）。阶段条件仍可在试玩后调整。三个阶段的背景音乐不同，由 FMOD 的交互音乐系统切换。

**当前实现**

- FMOD：`Mx_GamePlay` 里三层音乐时间线同步，全局连续参数 `GameStage`（0–2）控制各层音量，参数上的 Seek 调制器把每次切换变成交叉淡变。0 = Stage 1，1 = Stage 2，2 = Stage 3。
- 游戏：每次购买或经济变化后检查进度，跨过里程碑时把 `GameStage` 设为 1 或 2；**只进不退**；重开游戏回到 0。
- 如果玩家先研究了完全自动化、还没做第三次价值突破，会直接从 0 进到 2（FMOD 的 Seek 会依次滑过 Stage 2）。
- 触发条件在 `scripts/disk_demo.gd` 开头的 `MUSIC_MID_BASE_VALUE_LEVEL`（3）和 `MUSIC_LATE_GOVERNANCE_LEVEL`（3）。

### 一局游戏怎么推进

1. 开局两座史莱姆巢穴，只有吸管。新巢穴不会出现（开局保护 60 秒，并且要先解锁捕网）。
2. 解锁捕网后，星球开始随机长出新巢穴，黏液怪、钻头怪陆续登场。
3. 研究"巢穴培育"后可以升级巢穴；研究"完全自动化"后，巢穴升到顶级会被驯服（变成花、自动产糖）。
4. 所有巢穴都自动化即通关。

### 推荐方案

| 阶段 | 开始条件 | 理由 |
|---|---|---|
| **早期** | 开局 | 熟悉吸管，经济起步 |
| **中期** | **第三次基础价值突破**（900 糖果，史莱姆 5→10 糖果） | 超过 400 糖果；是科技树中央的核心经济节点，几乎每个玩家都会买；买完后收入翻倍，玩法节奏明显加快。此时通常已解锁捕网、出现新物种 |
| **后期** | **研究完全自动化**（7500 糖果） | 整局最贵的一笔投入；买完后进入"逐个驯服巢穴、星球开花"的收尾阶段 |
| （结尾） | 通关（全部巢穴自动化） | 可另做一段结尾音乐或 stinger，不占用三个阶段 |

**参考时间线**：README 里的脚本自动试玩（调价前）记录，四次基础价值突破在 41／115／167／255 秒，第一座巢穴自动化 273 秒，全部完成 306 秒。按推荐方案，脚本里大约是：早期 0–167 秒、中期 167–约 265 秒、后期约 265–306 秒。脚本玩得比真人快很多，**真人时长需要试玩实测**；但可以看出后期相对较短，因为后期收入增长很快。后期音乐建议按"高潮、可以较短"来设计，或者把后期起点提前（见下面的备选）。

### 仍可讨论

## 需要制作人留意的点

- **试听方式**：打开项目按 F5 运行主游戏即可。鼠标悬停怪物开始吸；黏液怪巢穴解锁后，去有黏液的地面上吸怪，可以听到黏液效果。
- **开机时机是"锁定怪物"而不是"鼠标在星球上"**：只有真正在吸东西时吸尘器才响，空闲时安静。如果试玩觉得开关太频繁，可以改成"吸管在星球表面就开机"，或者调长 0.2 秒的关机缓冲。
- **原来的收集音效（WAV）已被替换**：吸走怪物改为 `SuckUp_Pop` + `Candy_Acquire`，捕网收获改为 `Candy_Nest`。如果 bank 缺失或加载失败，会自动退回原来的 WAV，游戏不会没声音。
- 怪物声音是全局的（2D），不分左右、不随距离变小；在星球全景里静音（见上方"近景 / 全景的声音规则"）。
- 切到星球总览、移到 UI 上时，吸管口会被视为离开黏液，可能先听到一声 Pop 再关机。试玩时如果觉得别扭，请反馈。

## 更新声音的流程

音频同事在 FMOD Studio 里改完声音后，Build 出三个文件（`Master.bank`、`Master.strings.bank`、`ProjectVacuum.bank`），覆盖到项目的 `bank/Desktop/` 文件夹即可。只要事件名不变，游戏不需要改代码。
