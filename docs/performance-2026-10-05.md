# 2026-10-05 玩法验证版性能优化记录

这次先固定压力负载找热点，再修改最重的循环，并分别复测 CPU 工作量和真实绘制帧耗时。第一轮固定压力场景的 CPU 稳态中位耗时从约 **20.46 ms 降到 8.39 ms**；真实绘制从 **80.10 ms/帧降到 56.73 ms/帧**。改成整块星球盘面后的第二轮当前值为 **6.865 ms CPU 工作量、55.099 ms 实际帧中位耗时**，详见第 7 节。两者测量范围不同，不能把 CPU 工作耗时换算成游戏帧率。

## 1. 先建立可重复的负载

- 引擎：Godot 4.7.2 stable Steam，本机安装路径 `C:\Program Files (x86)\Steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe`。
- CPU 基准：40 条持续移动的黏液轨迹、120 个怪物，固定 1/60 秒模拟步长，每轮 360 步，共三轮。每步分别计时轨迹老化、追加采样、网格刷新、地面接触和怪物更新。首轮预热后，用后两轮对比稳态。
- 绘制基准：同样的 40 条轨迹、120 个可见怪物，1280×800，Forward+ / D3D12，NVIDIA GeForce RTX 4060 Laptop GPU，关闭垂直同步。先运行 60 帧，再记录 240 帧的实际帧间隔。
- 基准直接构造固定实体，绕过巢穴生成、科技和 UI。因此性能改进不能归因于新版开局怪物更少，也不包含 UI 修改的收益。
- 两次绘制试验共用同一版地表和怪物脚本，只切换优化前/后的黏液实现。运行时未停止用户已有的 Godot 进程，因此数据仍可能受到其他进程、功耗和温度波动影响。

## 2. 找到的主要热点

原来的 `append_ground_point()` 每帧会重新投影整条历史轨迹；随后约 20 Hz 的网格刷新又重新投影一次。每次重建三层轨迹时，还会重新裁切全部顶点并分配相同的三角形索引。

地面接触查询也会反复读取 `Polygon2D` 的几何属性，对包围盒内的所有三角形直接计算重心坐标。120 个怪物与 40 条轨迹的固定压力负载会放大这些重复工作。相比之下，怪物移动/状态更新约 1 ms，暂时不是这组 CPU 负载的主要热点。

## 3. 实际修改

1. **历史轨迹只投影一次。** 追加或替换尾端采样时，只计算变化点的投影；过期、截短时同步移除对应缓存。近景/缩略图切换等地表几何变化仍通过 `refresh_surface()` 强制重投影。
2. **复用轨迹几何。** 三层轨迹共享按采样数量生成的三角形索引；缓存上次未裁切和已裁切的顶点，只重新裁切实际改变的顶点。保留原来的 20 Hz 网格更新频率、寿命、淡出和长度限制。
3. **简化接触查询。** 缓存绘制使用的顶点、透明度、三角形和每个三角形的包围盒。查询先做包围盒筛选，再按原公式检查三角形和透明度。主场景只给黏液怪维护每帧黏附状态，普通怪物在实际吸入时才查询脚下黏液；活跃轨迹来源用字典检查，避免反复线性查找。
4. **去掉轨迹额外抗锯齿。** 轨迹仍保留三层颜色和顶点透明度淡出，关闭 `Polygon2D.antialiased`。本机真实绘制对照显示这一步还有收益；压力截图已检查，连续路径和宽度仍清楚可读。
5. **减少主界面重复刷新。** 捕网冷却不再驱动整套 HUD 每帧重建；同一帧收到多个状态变更信号时合并刷新；科技按钮的 `StyleBox` 只在等级变化时创建。
6. **缩略图只显示地块和气泡。** 进入缩略图时隐藏近景怪物及其地面细节，人口由气泡表达，避免在缩略图中继续绘制全部个体。

没有降低怪物移动的模拟频率，也没有使用额外美术贴图来掩盖性能问题。

## 12. 2026-10-06：密集场景掉帧的实际修复

用户反馈 21 巢附近的密集近景掉帧，本轮重新测量当前版本。继续使用本机 Godot 4.7.2、RTX 4060 Laptop、Forward+ / D3D12，关闭垂直同步；未更改项目渲染后端或减少人口。其他用户进程和 Godot 编辑器保持运行，数字是本机有限负载实测，不是硬件或正式游戏的通用保证。

### 原因与改动

- **角色绘制批次过多。** 普通身体每帧由轮廓、眼睛、嘴、斑点等独立图元重建。现在把同一造型的身体与圆形阴影缓存在同一共享图集，分别应用原来的身体弹跳和阴影变换，使相邻同样式个体可合批。保持原几何造型和颜色；待机压缩同时缩放缓存五官，约有 4.5% 的轻微伸缩差别。吸取、脱附、牵引、喷出、抛落继续使用原来的实时几何，贵重标记仍单独绘制。没有增加外部美术素材。
- **活跃黏液超过 80 个时循环淘汰。** 原逻辑为了维持轨迹总数 80，不断淘汰仍在排液的来源，该来源下一帧又分配新场景。现在优先移除不活跃历史，活跃来源各保留一条连续轨迹；保留总量为 `max(mucus_trail_limit, 活跃来源数)`。来源停止后回落到历史预算，寿命和长度限制继续生效，不以性能修复为由限制人口。
- **屏幕外装饰层也持续重建。** 图集完成后的 90 帧诊断中，主场景处理平均 8.27 ms，其中黏液 7.69 ms、轨迹网格重建 6.01 ms；约 61% 的重建位于屏幕外。屏幕外现在只更新完全相同的轮廓接触数据、颜色透明度判定、路径和寿命，暂不构建另外两层装饰或上传 Polygon2D 数据；重新入镜立即补齐，不等待下个 20 Hz 周期。
- **输入触发无效表现刷新。** 悬停命中查询不再要求巢穴重绘；仅释放上一个吸取目标，不复制整个种群数组或逐个重置无关角色。拖动新增轻量旋转信号，不反复执行视图切换、总览聚类和布局工作。巢穴的表现变换没变时保留原绘制命令；隐藏设施不请求重绘。
